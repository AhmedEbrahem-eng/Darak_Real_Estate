## 2026-05-01 - [CRITICAL] IDOR and Improper Authorship Reassignment in Review Operations
**Vulnerability:** Review update and delete operations were accessible without authentication and lacked ownership checks (IDOR). Furthermore, the delete operation incorrectly reassigned the `user_id` of the review to the currently authenticated user before performing a soft delete, effectively corrupting historical authorship data.
**Learning:** Security middleware must be consistently applied to all destructive and sensitive routes. Repository methods should not assume that the caller has already performed authorization. Overwriting model attributes before deletion (especially with SoftDeletes) can lead to data integrity issues and loss of audit trails.
**Prevention:** Always group sensitive routes under authentication and authorization middleware. Implement explicit ownership or role-based checks within the repository or controller layer. Never modify core identity attributes of a record immediately before deletion unless it is a specific requirement (e.g., anonymization).
